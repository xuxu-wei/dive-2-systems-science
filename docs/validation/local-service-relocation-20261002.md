# 项目迁移后的启动修复

2026-10-02；修复双击“开始学习.cmd”后服务退出的问题。

- 根因：项目迁入 `my-repos` 后，`.venv` 的 editable 包链接仍指向旧目录；原 `tools/serve.py` 未加载当前项目的 `src`，日志报 `ModuleNotFoundError: systems_science`。
- 修复：服务入口从自身位置加载当前项目源码；本机通过 `python -m pip install --no-deps -e .` 更新包链接，Notebook 可以再次导入教学包。学习指南补充目录迁移后的修复命令。
- 回归：9 项定向测试通过，覆盖服务复用、工作区隔离、更新重启及判题保护；新增测试在含中文和空格的临时路径，从外部工作目录、禁用 editable 注册的独立解释器中验证启动与源码来源。
- 实测：根目录 CMD 的检查模式与默认打开模式均退出 0；首页、目录、练习目录与进度接口返回 200，服务工作区、内容及桌面会话匹配。从其他目录再次执行入口，服务会话保持不变。
- 教材内容、判题规则与已有学习记录未修改；本地虚拟环境和日志不纳入版本管理。

2026-10-03：进一步改为自动维护相对包路径，消除每次迁移后的手工重装步骤。

- 本项目 `.venv` 的专有 `.pth` 写入 `../../../src`；先于 pip 的 editable 链接加载，旧目录仍存在时也优先导入当前副本。服务启动与 Notebook 共用入口会幂等维护该文件，更新使用原子替换。
- 写入限定项目内的实际 `.venv` 及其 site-packages；其他解释器、外部包目录或指向共享环境的 junction 均不修改。
- 15 项定向测试通过：真实临时虚拟环境随项目移动、复制且保留旧链接、中文/空格路径、外部工作目录、重复设置、外部环境隔离及原有服务检查。当前项目新进程的包来源和启动入口均已实测正常。
- 支持的是同机项目目录迁移；Python 基础解释器及其他工具安装位置仍属于机器环境，跨电脑使用按 README 重建环境。
